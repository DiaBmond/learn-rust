# Glossary

## Crate

A crate is a unit of compilation in Rust. For example, `src/main.rs` is the crate root of a binary crate. A crate can contain multiple modules, which may be spread across multiple files. A package can contain multiple binary crates.

### Binary Crate

A binary crate compiles into an executable program and must have a `main` function. A package can contain multiple binary crates, each with its own `main` function.

### Library Crate

A library crate provides functionality for other code to use and does not have a `main` function. A package can contain at most one library crate.

## Package

A package is a collection of one or more crates managed by Cargo. It contains a `Cargo.toml` file.

A package:

- must contain at least one crate
- can contain multiple binary crates
- can contain at most one library crate

## Associated Function

A function that belongs to a type, does not take `self`, and is called using `::`, for example, `String::new()`.

## Statement

A statement is an instruction that performs some action and does not return a value.

## Expression

An expression evaluates to a value.

## Unit Type

The unit type `()` represents the absence of a meaningful value. A function that does not return a meaningful value implicitly returns `()`.

## Stack

A region of memory that stores values in last-in, first-out (LIFO) order. Data stored on the stack has a known, fixed size.

## Heap

A region of memory used for dynamically allocated data. Data on the heap is accessed through a pointer.

## Borrowing

Borrowing allows code to access a value through a reference without taking ownership of it.

## Reference

A reference allows access to a value without taking ownership. References are created using `&`, and mutable references use `&mut`.

## Struct

A struct is a custom data type that groups related values together.

## Enum

An enum defines a type by listing its possible variants.

## Variant

A variant is one possible value of an enum. Each variant can store different types and amounts of data.

## Method

A method is a function defined inside an `impl` block that takes `self`, `&self`, or `&mut self` as its first parameter.

## Pattern Matching

Pattern matching compares a value against patterns and can destructure data stored inside enums and other types.

## Module

A module organizes related code inside a crate. Modules can be nested and can be defined in separate files.

## Generic Type Parameter

A placeholder for a concrete type, such as `T` in `Point<T>`.

Generics allow functions, structs, enums, and methods to work with different types without duplicating code.

## Trait

A trait defines shared behavior through methods. A type implements a trait using `impl Trait for Type`.

## Trait Bound

A constraint that requires a type to implement a specific trait.

For example, `T: Summary` allows generic code to use methods defined by `Summary`.

## Blanket Implementation

A trait implementation that applies to every type satisfying certain trait bounds.

For example, `impl<T: Display> Describe for T` implements `Describe` for all types that implement `Display`.

## Borrow Checker

The part of the Rust compiler that enforces borrowing and lifetime rules to ensure references are valid.

## Dangling Reference

A reference that points to data that is no longer valid. Rust's borrow checker prevents code from using dangling references.

## Lifetime

The period during which a reference is valid. Rust often infers lifetimes automatically.

## Generic Lifetime Parameter

A named lifetime parameter, such as `'a`, used to express relationships between references in functions, structs, and methods.

## Lifetime Annotation

Syntax such as `'a` that expresses lifetime constraints between references.

Lifetime annotations do not change how long values live.

## Lifetime Elision

A set of rules that allows the compiler to infer lifetime relationships in function and method signatures without explicit annotations.

## `'static` Lifetime

A lifetime that can last for the entire duration of a program.

String literals have the type `&'static str`. A variable holding a `'static` reference does not itself need to remain in scope for the entire program.

## Unit Test

A test that verifies the behavior of an individual function, method, or small part of a program.

In Rust, unit tests are commonly defined in a `tests` module within the source file.

## Test Function

A function marked with `#[test]` that the Rust test framework executes to verify expected behavior.

A test normally passes when it completes without panicking and its assertions succeed.

## Test Runner

The component that executes tests and reports whether they passed, failed, or were ignored.

## Test Harness

The testing infrastructure generated by Rust that discovers test functions, executes them, and reports their results.

## Assertion

A check that verifies whether a condition or comparison matches the expected behavior.

An assertion failure causes a test to fail.

## `assert!` Macro

A macro that checks whether a Boolean expression evaluates to `true`.

If the expression evaluates to `false`, the macro panics.

## `assert_eq!` Macro

A macro that checks whether two values are equal using `==`.

If the values are different, the macro panics and displays both values using debug formatting.

## `assert_ne!` Macro

A macro that checks whether two values are different using `!=`.

If the values are equal, the macro panics and displays both values using debug formatting.

## Custom Failure Message

An additional message provided to an assertion macro to explain why a test failed.

Custom failure messages support formatting syntax such as `{}` and named variable capture.

## `PartialEq` Trait

A trait that supports equality and inequality comparisons using `==` and `!=`.

Custom structs and enums can often implement this trait using `#[derive(PartialEq)]`.

## `Debug` Trait

A trait that allows values to be formatted for debugging using `{:?}`.

The `assert_eq!` and `assert_ne!` macros require compared values to implement `Debug` so they can display them when an assertion fails.

## Panic

A mechanism used when a program encounters a situation it cannot or should not continue from normally.

In ordinary tests, an unexpected panic causes the test to fail.

## `#[should_panic]` Attribute

An attribute that marks a test as expecting a panic.

The test passes if a panic occurs and fails if no panic occurs.

The optional `expected` parameter checks whether the panic message contains a specified substring.

## `#[ignore]` Attribute

An attribute that skips a test during a normal test run.

An ignored test is not considered passed or failed. It can be executed explicitly using the `--ignored` test runner option.

## `#[cfg(test)]` Attribute

A conditional compilation attribute that includes code when the `test` configuration is enabled.

It is commonly used to define modules containing unit tests.

## Result-Based Test

A test function that returns `Result<(), E>` to indicate success or failure.

Returning `Ok(())` passes the test, while returning `Err(error)` fails the test without requiring a panic.

## Error Propagation

The process of returning an error from a function to its caller.

In Rust, the `?` operator propagates an `Err` value and allows a result-based test to fail when an operation returns an error.

## Regression

A bug introduced by a code change that causes previously working behavior to stop working correctly.

Automated tests help detect regressions when implementations are modified.
